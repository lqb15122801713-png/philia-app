# 分账合规设计稿 · 之一：跨店消费结算（消费分账 D+1）

> 性质=**设计稿，不落码**（任务书冻结版 V1.0 §二：分账三件=先出合规设计稿呈老板本人过目，过目后才许落码）｜ 起草=产品侧+A 窗（施工方代笔）｜ 2026-10-07。
> **总闸（不可谈判）**：系统**只算账出报表、不接真分账不动真钱**——算账 vs 清结算分离。本稿定义「账怎么算、留痕什么形状、报表长什么样」，**不含任何支付通道、代扣、划转、备付金动作**。

## 一、口径（算账 vs 清结算分离）

| 层 | 内容 | 边界 |
|---|---|---|
| 算账（系统做） | 按日聚合「A 店客户（卡办在 B 店）在 A 店消费」的实收额，产出**店间应收应付对账单**（消费店=应收方，办卡店=应付方） | 仅台账与报表，不产生任何资金动作 |
| 清结算（系统不做） | 真实的店间划转/代扣/归集 | **线下自行处理**（老板对公转账惯例）；系统侧只留「线下结清登记」留痕 |

- **结算单元**：自然日（D+1 出前一日对账单，T+1 上午可见）。
- **金额口径**：实收（computeDayTender 同源=现金类段+预约直收；次卡扣次/储值消费/回馈金抵扣=参考列单列，**不计入可分账实收**——非现金权益消耗=办卡店已承担的负债，不进跨店结算）。
- **费率**：v1=全额（100% 归消费店）；费率参数留口 `chain_settle_fee_bp`（service_rules 端口键，缺省 10000，老板可调）。
- **时点口径**：以支付段 createdAt/预约 paidAt 落自然日（+8 门店墙钟，与日结同源）。

## 二、数据结构（留痕形状，未落码）

### 2.1 店间对账单 `chain_settle_statements`（台账，只增不改）

| 列 | 型 | 说明 |
|---|---|---|
| id | ULID | 单号 `ST-yyyymmdd-NNN` |
| biz_date | date | 结算日（消费发生自然日） |
| from_store_id | text | 应付方=办卡店（memberships.sold_store_id） |
| to_store_id | text | 应收方=消费店（cashier_bills/appointments.store_id） |
| gross_fen | int | 实收毛额（现金类） |
| fee_bp | int | 费率快照（缺省 10000） |
| net_fen | int | 应付净额=gross×fee_bp |
| ref_json | json | 单据锚清单 [{billNo/apptId, fen}]（对账可溯，**不带个人信息**） |
| status | text | `draft`（系统出账）→ `confirmed`（双方店长确认）→ `settled`（线下结清登记） |
| settled_note | text | 线下结清注记（转账日期/凭证号，**手工登记**） |
| created_at/updated_at | ts | 审计列 |

### 2.2 结清登记 `chain_settle_confirmations`（留痕）

`{ id, statement_id, action: confirm|settle|dispute, by, note, at }`——**状态机只增不改**；dispute 行=争议注记（不阻塞后续出账，列入下一日对账备注）。

## 三、出账与报表（读口形状）

- **出账**：日结后懒生成（首个次日访问触发 or 定时滴答 02:30，幂等锚 `(biz_date, from_store, to_store)` 唯一）。
- **老板端报表**：三店互转矩阵（from×to 净额）+ 日序列 + 未结清余额（Σconfirmed−Σsettled）；**与日结同源出口对账**（对账单 gross 合计=当日跨店消费实收合计，对账钉）。
- **导出**：CSV（照 refund.exportCsv 工艺：固定列+BOM+导出留痕）。

## 四、合规红线（写死）

1. 全程**零 pay_orders/payments 写**（不碰真钱实证=e2e 断言零新行）；
2. 不收客户第二笔钱、不动会员余额、不动储值/回馈金/次卡负债口径；
3. 线下结清=手工登记留痕，系统**永不**执行/发起/指令资金划转；
4. 反洗钱/二清边界：系统**不形成资金池**（无归集账户概念，归集件另见设计稿之三）。
