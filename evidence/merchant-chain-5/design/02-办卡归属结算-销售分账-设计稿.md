# 分账合规设计稿 · 之二：办卡归属结算（销售分账）

> 性质=**设计稿，不落码**（老板本人过目后才许落码）｜ 起草=产品侧+A 窗｜ 2026-10-07。
> **总闸**：系统**只算账出报表、不接真分账不动真钱**（算账 vs 清结算分离）。

## 一、口径

- **既有地基（已落码在仓）**：`memberships.sold_store_id`（决策 #41 双归属：售卡店=sold_store，消费店=单据店）+售卡提成定额（员工向：萤火 500/烛光 1000 分，e2e R11a⑩ 实证在仓）。
- **本件=店向销售分账**：售卡店每售一张付费会员卡，形成对**品牌总部（或指定归集店）的销售分成账**——系统只出**月结对账单**，费率端口留口。

| 层 | 内容 | 边界 |
|---|---|---|
| 算账（系统做） | 按月聚合各店售卡实收（memberships.paid_fen，status≠cancelled），按费率拆出「店留/上缴」两列，出**售卡分账月报** | 仅台账与报表 |
| 清结算（系统不做） | 上缴资金的划转 | 线下处理，系统只留「结清登记」留痕 |

- **费率**：`chain_card_share_bp`（service_rules 端口键，缺省 8000=店留 80%/上缴 20%，老板可改）。
- **退费冲减**：退会（cancelled+refund_fen>0）在**退款发生月**按同费率红字冲减（前后值留痕，CJ-0922-13 退会折算口径不变）。
- **员工提成与店向分账两本账不混**（员工提成=commission 域既有件；店向分账=本件，口径注记明面）。

## 二、数据结构（留痕形状，未落码）

### 2.1 售卡分账月报 `chain_card_share_monthly`（台账，只增不改）

| 列 | 型 | 说明 |
|---|---|---|
| id | ULID | 单号 `CS-yyyymm-店序` |
| month | text | 归属月 YYYY-MM |
| store_id | text | 售卡店 |
| gross_fen | int | 售卡实收（Σ paid_fen，新增/续费分列） |
| refund_fen | int | 当月退会红字冲减 |
| share_bp | int | 费率快照 |
| keep_fen | int | 店留=gross×(1−bp)+红字按同率 |
| remit_fen | int | 上缴=gross×bp−红字按同率 |
| status | text | `draft` → `confirmed` → `settled`（线下结清登记） |
| created_at/updated_at | ts | 审计列 |

### 2.2 留痕

`chain_card_share_logs`：`{ id, monthly_id, action, by, note, at }`（confirm/settle/adjust 调整注记只增不改）。

## 三、报表形状

- 老板端：月度三店对比卡（售卡实收/店留/上缴）+ 年度累计 + 未结清月数；
- 对账钉：月报 gross 合计=membership.amortizationStats 当月售卡实收同值（既有读口同源对账）。

## 四、合规红线

1. 零支付通道写（e2e 断言零 pay_orders/payments 新行）；
2. 退会冲减只动分账报表，不回改 memberships/refund 既有行；
3. 费率变更=端口行留痕（rule_config_versions 既有机制），历史月报按当时快照 bp 不重算。
