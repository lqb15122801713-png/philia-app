## 一、断网检测与状态展示

1. **双判**：`navigator.onLine` 变化事件 + 打卡请求网络层失败（超时/5xx 不计——服务端错误走普通错误态，不算离线）；
2. **离线状态条**：打卡页顶部常显细条（设计内组件，非原生弹窗）："当前离线，打卡将先存在本机"＋暂存条数（>0 时带数）；恢复在线条消失并触发补传；
3. 打卡按钮离线不置灰（允许离线打，走暂存）——按钮文案变"离线打卡·先存本机"（明示，不静默）。

## 二、离线打卡流（暂存→补传）

1. **采集**：获取定位坐标（失败则按在线同款拒绝+明示，不因离线放宽围栏）＋**采集时刻**（设备时间）＋打卡类型（in/out）＋班次 id＋设备标记；
2. **本地暂存**：写入 IndexedDB（持久化，杀进程/重启不丢），暂存条目含全字段+暂存时刻；上限 10 条（满则阻止并明示"先联网补传"）；
3. **幂等**：同人同班次 in/out 各限一条——暂存期同类型再点=明示"已有暂存待补传"，不重复落（防离线反复打制造多卡）；
4. **补传**：恢复在线自动补传（FIFO，指数退避 2s/8s/30s，连续 3 次失败暂停并明示手动重试）；补传成功逐条 toast"离线打卡已补传"；
5. **时限**：补传截止=**当日 24:00**；超时未补传条目**冻结本地并转店长异常队列**（次日员工端提示一次"有 N 条离线打卡待处理"）。

## 三、真值与防代打（写死）

1. **双时间戳留痕**：attendance_records 落 `captured_at`（采集时刻）+ `uploaded_at`（补传时刻）+ `offline=true` 标记；考勤月表"离线补传"单列可见；
2. **围栏判定以采集时坐标为准**（非补传时坐标）——离线期间移动不影响判定；采集坐标与门店距离落痕同在线；
3. **设备时间校验**：上传时比对 captured_at 与服务器时间，偏差 >5 分钟标记"时间异常"进店长审批（不阻断，防改机时间补卡）；
4. 补传记录参与正常四态比对（正常/迟到/早退/缺卡）——按 captured_at 比班次，不按 uploaded_at（防"夜里补传全变早退"）；
5. 店长视图异常队列：离线补传条与补卡申请同队列，标"离线补传"来源，店长确认/驳回留痕（复用既有双流，不另建）。

## 四、边界与异常

| 场景 | 处置 |
|---|---|
| 离线时定位也失败 | 不采集、不暂存，明示"定位失败"（与在线同款，不因离线放水） |
| 暂存后设备丢失/清除数据 | 视为缺卡，走既有补卡申请流（员工说明情况，店长审批） |
| 补传时服务端已有同班次同类型卡 | 服务端幂等去重，返回已存在即视为补传成功（不造双卡） |
| 暂存满 10 条 | 阻止新暂存+明示先联网补传（防无限积压） |
| 弱网（高延迟非断网） | 请求超 10s 未响应转离线暂存流；计时口径按 QA：4G 节流 LCP 实测 |

## 五、验收口径（QA 对齐点）

1. e2e 增补：离线打卡暂存（IndexedDB 有行+状态条明示）→恢复补传（成功 toast+双时间戳落库）→围栏以采集时坐标判定→超时条转店长异常队列→时间异常 >5min 标记；
2. 掐表：离线打卡 ≤2 击（与在线同）；补传全自动零操作；
3. 弹窗口径：全部设计内组件，零原生 alert/confirm/prompt；
4. 数据确认：attendance_records 三新字段（captured_at/uploaded_at/offline）+月表"离线补传"单列。
