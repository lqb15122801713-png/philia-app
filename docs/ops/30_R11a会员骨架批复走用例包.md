## 〇、执行口径（动手前先读）

1. **分工（CJ-0921-07 不变）**：真机操作 = 产品侧 / 门店；QA 出用例、收证据、下判定。无证据不判定。
2. **证据链**：每条用例须留——机型 / 系统 / 浏览器 / 网络态、录屏或连续截图、计时读数（掐表法照 13 号档 §八）。
3. **计时纪律**：每条计时用例测 3 次，最大值与中位数双记，最大值超线即 ❌；计时统一口径 = 4G 节流 LCP。
4. **弹窗口径（已定）**：零弹窗 = 原生 alert/confirm/prompt 及营销、授权类打断弹窗为 0；设计内确认流（重确认 D 套、toast、离线状态条等）不计。立省钩子「一屏一次不打扰」按此口径核。
5. **双层标记分离**：本包只判「功能实现已确认」；「数据结构已确认」归监理（Kimi Code B 窗，唯一出口 CJ-0923-02）。
6. **QA 边界**：只上报不指挥施工；改进方向为建议性质，方案归产品经理。
7. **判定词**：✅通过=真机/走测证据充分（注明来源）；⚠️部分通过=主链路已证、子项待证（列明）；❌不通过=证据证伪或冻结规范违反；待实测=无有效证据。
8. **V1.0 判定基线**：本版为**用例冻结版**——全部条目判定=待实测，待产品侧/门店真机执行回证后逐轮回填。
9. **B 窗证据引用纪律**：B 窗《R11a 可执行核查报告》（实证版）的 e2e/代码级实证（钱红线探针五条等）可作**辅证**引用并注明来源；体验条款、页面呈现、真机计时判定仍以真机走测证据为准——监理实证不替代真机。

## 十二、反对意见与风险（军规一）

1. **定时器类不可真机等测**：回馈金月度到账（次月 5 日）/365 天到期冻结——归监理（B 窗）代码级核查+产品侧注入实证，QA 不背；本包只验页面口径与批次单呈现（C2-01/C4-01 主体待注入实证）。
2. **连锁双归属三店实证前置缺口**：当前仅一店在线，跨店通用（E2-02）只能核字段与配置——真三店实证待连锁合批，届时本用例回归。
3. **内测期「到店付」口径**：售卡无线上支付通道，资金实收证据=收银台收款留痕——请产品侧提供内测期到店付的留痕样例，防「开通确认点了他没付钱」的第三态。
4. **会员页=R11a 骨架版**：本批不评美观（R11b 后置），但「规则明面」（红线 5）是功能项必须验——骨架版若把规则藏进折叠/二级菜单，照红线判 ❌，不因「等视觉件」放水。
5. **立省钩子与零弹窗的边界**：钩子必须是设计内卡片形态且一屏一次——若实现为打断式弹层，按零弹窗条款判 ❌。
6. **回馈金扣回与 R12 的接缝**：C5-01 是跨批接缝用例（R12 冻结接口×R11a 启用）——两批各自的 e2e 都绿不等于接缝绿，必须真退款一单商品单实证。
7. **范围核对两件（H4-02）**：APP-07 档位预约权益与 APP-04 续费提醒在 04a 标「R11 随批」但未列入 28 号施工令八项——登记待产品侧书面澄清去向批次，QA 不自行裁决。
8. **测试数据需求（请产品侧/运营备）**：①三档付费会员各 1 号（含 1 个多宠 4 只暖阳号）；②有回馈金余额且部分临期的账号 1 个；③无余额新微光号 1 个；④含商品+服务混合单、纯商品单、寄养单的可退订单各 1 笔——备齐后半天可走完主链路。
