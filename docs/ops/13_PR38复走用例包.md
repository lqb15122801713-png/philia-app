## 〇、执行口径（动手前先读）

1. **分工（CJ-0921-07）**：真机操作 = 运营 / 门店；QA 出用例、收证据、下判定。本包全部用例判定栏初始 = **待实测**——代码覆盖 ≠ 体验达标，施工方自报不作数。
2. **证据链（无证据不判定）**：每条用例须留——机型 / 系统 / 浏览器（或微信内）/ 网络态（WiFi / 4G / 节流 / 断网）、操作录屏或连续截图、计时读数（掐表法见 §八）。证据命名：`QA38-<用例号>-<机型>-<日期>`（PR #38 域）/ **`QA39-<用例号>-<机型>-<日期>`（R12 域）**，归 evidence 体系永久保留。
3. **计时纪律**：计时复核两遍（军规二 QA harness）。每条计时用例测 3 次，**最大值与中位数双记**，最大值超线即 ❌。计时统一口径 = 4G 节流 LCP（CJ-0921-12⑤ 采纳）。
4. **弹窗口径（已定，CJ-0921-12⑤ 采纳 QA 暂行口径）**：「零弹窗」= 浏览器原生 alert / confirm / prompt 及营销、授权类打断弹窗为 0；设计内页面级确认流（重确认 D 套、离线状态条、toast、退款预览页等）不计入。
5. **双层标记分离**：本包只判「功能实现已确认」；「数据结构已确认」归监理核查域，本包不标。
6. **QA 边界**：只上报不指挥施工；改进方向为建议性质，方案归产品经理。

## 八、掐表与击数口径（计时方法学）

1. **击数**：手指有效点击次数，页面就绪后起算；聚焦输入计 1 击，逐字输入不计。离线打卡击数与在线同口径（≤2 击，17 号 §五.2）。
2. **计时**：录屏逐帧读数（30fps 下帧粒度 33ms）或系统秒表 + 录屏双轨互校；LCP 用 DevTools Performance（4G 节流预设，已定口径）。每用例 3 次，最大值 + 中位数双记，最大值超线即 ❌。
3. **补传节奏观测**：退避 2s/8s/30s 不肉眼估——以录屏时间轴 + 服务端 uploaded_at 落库时刻差互核。
4. **环境登记**：机型 / OS / 浏览器或微信 / 网络态 / 电量；低端机动效降级单独标注；改机时间类用例测后必须恢复设备时间。
5. **R12 无专项计时条款**（退款非高频效率操作，不设击数/时长线）；体验关仅加载 <2s（F5-03）+ 零弹窗（F5-02），口径既定。
6. **读数不得编造**：测不到就标「待实测」，不估不凑。
