## 〇、批次定位与两个概念划清（全批的纲）

**退款 ≠ 反结账**，两通道并存、口径分清、互不借用：
| | 反结账（既有，不动） | **退款（本批新建）** |
|---|---|---|
| 性质 | 错单纠正（店主冲正） | 客户侧真实退款（经营行为） |
| 发起 | 仅店主 | 店长（手机上批）/店主 |
| 钱口径 | **不计当日已收**（冲正关联单） | **计退款列**（当日经营流水的负向单列，日结"退款单列"呈现——APP-40 口径） |
| 账呈现 | 原单灰签+冲正关联单双向可查 | 原单永存+退款单关联双向可查，原单状态→已退款（部分退款→部分退款） |
| 库存/储值/次卡 | 自动回补（既有） | 自动回补（本批同款，走 stock_movements 流水） |

**边界（写死）**：①不动反结账既有逻辑；②年费会员退卡/回馈金清零=R11 会员批（回馈金未上线，本批不涉及回馈金任何动作）；③线上支付通道（微信/支付宝 API 自动退）未接入——本批退款"钱"的实退动作=**内测期线下原路退回+系统内"实退完成"标记**（通道期换装为 API 自动退，接口预留）；④储值退款=退回储值账户（余额回补留痕），不退现金（三本账口径）；⑤UI 工艺件自装。

## 二、退款场景全覆盖（五类，逐类口径）

1. **未支付单**：不涉及钱——沿用既有撤单（clerk 可撤未支付单，补丁①），不在本批；
2. **已支付单全额退款**：全额原路退回；支付段逐段回补（现金段→退现金标记；微信/支付宝段→线下原路+实退标记；**储值段→余额回补**（前后余额留痕）；**次卡段→次数回补**（pass_deduct_logs 正向行+note 关联））；商品行→库存回补（stock_movements source='refund'）；预约行→paid_at/paid_fen 清零回待收款口径（如已核销/已服务则禁止退款转店长特批）；
3. **已支付单部分退款（按行/按金额）**：选行退或输入金额退；按行退=该行全联动（该行商品回补/储值次卡按比例回补）；按金额退=按比例分摊回补（分摊口径页面明示）；部分退款单可再退（余额内）；
4. **预约未到店退款（已支付未服务）**：预约取消+已收款退款二连（既有取消流+本批退款链接入）；
5. **次卡退卡**：按剩余次数×（实付/总次数）折算退款额，退到储值账户或线下原路（二选一，页面必选+留痕——折算公式明示，防纠纷）；**次卡退卡后卡作废留痕**。

## 三、流程与状态机

发起（店长视图/商家端：选单→选类型（全额/按行/按金额/退卡）→填原因→预览联动清单（退什么钱/补什么货/回什么余额，**明示五联动**）→重确认 D 套）→执行（同事务五联动）→退款单（refund_bills：单号 RB-yyyymmdd-NNN、关联原单、类型、金额、原因、操作人、审批人、实退方式、实退标记）→实退登记（内测期：线下退完后点"实退完成"+可附备注；超 24h 未登记进店长待办提醒）→日结"退款单列"自动汇入。
状态机：draft→executed（账已联动）→settled（实退完成）；店长可驳回 draft（驳回留痕）；**executed 后不可撤销**（要纠错=再开一笔正单，不许反向涂改）。
