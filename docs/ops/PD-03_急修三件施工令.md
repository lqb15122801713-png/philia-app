## 一、范围（三件，全部小改动面）

### 件 1 · QA40-D13（D-17）联合支付应收回写（钱域显示，最急）

实证根因（产品侧坐实，代码级）：①`apps/merchant/src/components/cashier/PaySheet.tsx` 明细行「实收 ¥X − 应收 ¥Y」的「应收」实为 `min(cashApplied, moneyNeedFen)`——**标签误用**：店员手改现金后该位把「现金承担额」显示成「应收」（老板 9-24 亲测「应收被回写 168→160」即此）；②现金/微信/支付宝金额输入框 onChange 只写自己不触发 `rebalance()`（再平衡只在胶囊/储值/回馈金开合时跑）→ 三项联合支付手改任一段后 Σ≠应收→确认钮锁死且无差额提示，实收/找零同步失真。

**修法（单文件）**：
1. 明细行标签「应收 ¥Y」改为「现金承担 ¥Y」——应收唯一真值=顶部大数字（dueFen），任何位置不许把分段金额叫「应收」；
2. 现金类输入框 onChange 触发再平衡：改动段固定，其余选中段的**末位**兜底差额（`rebalance` 复用，改动段从 others 剔除）；
3. 差额提示行实时明示：Σ≠应收时显示「还差 ¥X / 超出 ¥X」（确认钮锁死原因可见）；
4. 现金手输同步刷 `cashReceived`（实收/找零不滞后）。

### 件 3 · D-16 自助开户（CJ-0925-07 老板已批）

实证根因：dev-login 服务端硬约束仅放种子用户（`kimi_id` 须 `seed_` 前缀），新手机号成不了账号=注册链路断。

**修法（CJ-0925-07 批准口径）**：
1. server `auth/devLogin.ts` 加手机号分支：口令门校验通过后，body 带 `phone`（格式 `1\d{10}`）→ 查 users.phone：存在=直接登录；**不存在=建档**（kimi_id=`phone:<手机号>`、nickname=`新客 <尾4位>`、user_roles+customer——照 membership.sell 旁路建档同构）→签会话；
