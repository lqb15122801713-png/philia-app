## 一、码上现状（实证）

商家端 rail 现四组+foot：**经营**（总览/预约/寄养/收银台/日结/退款）· **商城**（订单/商品/会员次卡）· **管理**（员工/审批中心→/ops/监控 Hub/报表/权限矩阵/门店档案·设置）· **批次扩口**（排班→/settings/schedules / 运营→/ops / 薪资→/payroll / XP 审核→/xp-admin）· foot=开发者管理端（/console+owner 三子行）。

两处歧义实证：①**「审批中心」（管理组）与「运营」（批次扩口组）同指 /ops**——同一目的两口，/ops 页内四区（PDCA 闭环/自检审核/巡检汇总/指标申诉复核）本就是审批+运营一体面；②**dock「我的」槽映射 /settings**（门店档案·设置）——「我的」名与实不符。

## 二、件 1 · 批次扩口四口归位正式 rail 组（转正稿）

**批次扩口组撤销，四口全部归位「管理」组**（四口全部是管事/管人件，归位后管理组 9 口，按人→事→治理排序）：

| 组 | 口序（转正后） | 归位来源 |
|---|---|---|
| 经营 | 总览·驾驶舱 / 门店端·预约 / 寄养 / 收银台 / 日结 / 退款 | 不变 |
| 商城 | 商城订单 / 商品 / 会员·次卡 | 不变 |
| **管理** | **员工 / 排班 / 薪资 / XP 审核 / 运营·审批中心 / 监控 Hub / 报表 / 权限矩阵 / 门店档案·设置** | 排班←批次扩口（贴员工）；薪资←批次扩口（贴排班）；XP 审核←批次扩口（贴薪资）；运营←批次扩口+管理组审批中心**合并为一口**（见 §三） |
| foot | 开发者管理端（/console+owner 三子行） | 不变 |

**归位理由（一句）**：四口全是「管人/管事」件，与员工/审批同域——单列「批次扩口」组是施工期临时脚手架，批次收口即拆，不让临时结构长成永久结构。

**纪律对齐**：rail 口数变更=M1 件「口数变更须老板定」——本稿即呈批件，老板一句话留痕即转正；icon 沿用 lucide 线性族（排班 CalendarRange/薪资 Wallet/XP Sparkles/运营 ClipboardCheck 已在码，零新画）；bd 角标槽、clerk 白名单（仅收银台）、断点双形态全部不变。

## 三、件 2 · 「/ops 双入口」消歧

**合并为一口：管理组「运营 · 审批中心」→ /ops。**
- 删批次扩口组「运营」行；管理组原「审批中心」行改名「运营 · 审批中心」；
- 同名同图同屏，/ops 落屏时只有一口高亮——双高亮消失；
- 页内不动（四区本就是一体面：PDCA/自检审核/巡检/申诉复核）；
- 若日后审批待办要独立露出：用该口 bd 角标承载计数（审批+申诉合并计数），不拆口。

## 四、件 3 · dock「我的」槽映射转正（我建议，产品侧裁）

**我的建议：槽名改「设置」，维持指 /settings，废掉「我的」映射。**
- 理由：商家端=经营面不是个人面，「我的」是客户端/员工端概念（身份/提成/XP）——硬套「我的」映射设置页，名不副实、员工点进去找不到「我」；
- 方案 A（推荐）：第五槽名=「设置」，指 /settings 不变——零新页、零语义债、立刻转正；
- 方案 B：新建商家端轻量「我的」页（账号卡+通知偏好+设置入口+退出登录）——语义最正但=新页出生，归补缺专项不随片 6；
- **取舍账**：A=现在就对（命名对齐原则）；B=更对但慢。建议 A 先落地，B 登记候补（运营走查若报「找不到退出/账号」再启 B）。
