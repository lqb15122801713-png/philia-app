# PM-1009-2 · 菲利亚模型行业巡查报告（2026-10-09，老板全景交底后的学习汇报）

> 老板交底：菲利亚科技有限公司=主体（宠物服务）；门店=线下体验触点；客户=总公司流量池；钱=全进总公司；门店业绩单独核算；瑞幸模型。「别急着下结论，告诉我你了解了什么。」

## 一、这套系统在行业的名字
连锁品牌数字化体系，通用叫法=**「总部流量池+门店履约」/「大中台+小门店」**，系统形态=S2B2C（总部-门店-客户）。瑞幸自己的叫法=**ONE SYSTEM**：前端交互系统+运营系统+数据分析系统，一套系统管到底（选址到运营到人才培养全覆盖）。

## 二、瑞幸怎么做的（多源实证）
- **客户=总部私域流量池**：CDP 模式，APP+小程序+企微多触点汇入一池，营销规则自动化超 90%；
- **门店=履约触点**：自提店为主+自动化排班/订货/效期管理/设备监控，店员操作极简；
- **钱与账**：总部统一收，门店单独核算业绩（直营+联营体系）；
- **技术底座**：混合双云支撑 500 万日单（2022 年），为规模化预留。

## 三、行业通用做法（连锁 SaaS 多源一致）
1. **客户资产归品牌方**（总部流量池），门店会员跨店通用（积分/储值/等级通兑）——「会员局限单店=连锁做不大的核心原因」（乔拓云等口径）；
2. 门店业绩/提成**单独核算**，总部统一管商品/价格/营销，门店在授权范围内操作（账号池分级权限）；
3. 分层数据看板：总部看全局，门店看本店；
4. 开源/案例参照：scm-biz-suite（总部-省-市-门店多角色开源演示）、fuint/mms（会员营销 SaaS）、数商云 S2B2C 连锁实践（统一会员中心+门店分销归集+分层看板）。

## 四、对我们系统的对账（了解了什么）
- 老板这盘棋**与行业主流完全一致**，而且你的「钱全进总公司、不存在店间分账」（CJ-1007-01）早就是这套逻辑的伏笔——分账三件作废裁得对；
- 我们已建的恰好对得上：连锁两层+数据隔离+三店驾驶舱+会员体系+端口化；
- **需要校正的一个概念**（老板 10-09 质疑触发）：客户「归属」概念从店级改为**总公司流量池**——门店只是业绩核算标签+履约触点；服务层不认归属（任何店可服务）已裁（CJ-1009-02② 澄清口径）；
- 客户迁移：老板令=先不做，「数据就是导入导出一件事」——迁移执行包降优先级，先做能用的。

## 五、行业踩坑警戒（顺手带回）
- 加盟/直营混合体系的分账结算是后期深水区（咱们=直营全收总公司，暂无此坑）；
- 总部权限太死会憋死门店经营（账号池「管得住、放得开」原则）——与我们「能调=最基本」纲领同款。
