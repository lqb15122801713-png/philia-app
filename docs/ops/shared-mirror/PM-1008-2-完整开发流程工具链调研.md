# PM-03 · 完整开发流程工具链调研（2026-10-08 第二圈，老板极致授权）

> 老板令：「有没有可以调教 Agent 开发出一套非常好用的三端 app 的工具……完整的开发流程需要的内容再扫一圈，不光是踩过的坑。」定位前提=CJ-1008-07：**通用三端系统，全国 100/1000 家可用，没有切换日**。
> 按开发全流程排：设计→调教 agent→开发→测试→评审→部署→运营监控→触达→规模化。

## 一、设计稿→代码：screenshot-to-code（abi，34k★，开源）
- UX 稿/截图/Figma 直接转 React+Tailwind 代码，多模型可选，本地可部署；
- **适配点**：UX 出稿→A 窗施工的链路加一道「稿转骨架」，A 窗从骨架起手而不是从零摆页面；
- **边界（诚实）**：生成的是视觉骨架，业务逻辑/数据链仍 A 窗写；可维护红线（CJ-1008-01）照查不误；
- **建议**：UX+A 窗试一屏（如首页改版方向稿回来即试），评「省几成」。

## 二、调教 agent：AGENTS.md 规范对齐 + promptfoo 评测闸（24.3k★，MIT）
- **AGENTS.md**：开源界正在收敛的「agent 角色说明书」标准格式——我们角色卡体系（①~⑨）思路同款，建议格式对齐（零成本，提高与未来工具的兼容性）；
- **promptfoo**：调教 agent 的评测闸——角色卡/提示词每改一次，跑一遍回归评测（ benchmark 固化「好 agent 该答对什么」），**防越改越笨**；自带红队安全测试；
- **适配点**：角色卡⑧⑨修订（如 V2.2 可维护红线）到底有没有让 A/B 窗更靠谱，从此有尺量；
- **建议**：PM 牵头建评测基线（每窗 10-20 条考题），QA 协理。

## 三、生产运营三件套（自托管 Docker 件，VPS 可养）
| 件 | 管什么 | 治我们什么 |
|---|---|---|
| **GlitchTip**（Sentry 兼容 SDK） | 三端报错自动收集+聚合+告警 | 「线上问题靠老板随手一点撞见」——以后错误自己送上门，带堆栈 |
| **Uptime Kuma** | 可用性盯梢+状态页 | 三端死活一眼绿点，宕机秒告警 |
| **Umami** | 访问分析（隐私友好无 Cookie） | 真实客户用了什么、卡在哪页 |
- **建议**：GlitchTip 优先（对接成本=改一行 DSN）；三件可与 Langfuse 同批上 VPS（CJ-1008-06④ 中期包合并）。

## 四、触达通道：Novu（22.9k★，MIT 核心）
- 一条 API 多渠道：站内信/邮件/短信/推送/聊天，工作流编排（「站内 10 分钟未读→短信」）、聚合防轰炸、用户偏好、**可嵌入 React 通知中心组件现成**；
- **适配点**：缺口台账第一梯队「通知通道」+预约提醒/临期提醒/审批待办推送；我们已有站内信骨架，Novu 补全多渠道；
- **边界**：短信/推送落地仍要国内通道资质（与资质三件联动）；可先自托管跑站内信+邮件，短信后接；
- **建议**：线上化专项/触达批立项时首选评估。

## 五、规模化（全国 100/1000 家方向）：不搬脚手架，吸收设计点
- 扫了中文圈多租户 SaaS 脚手架（若依租户版/vctgo/goadmin 等）——**全是 Java/Vue 体系，与我们 Node+React 栈不合，不搬**（换栈=找死，零建议）；
- **要吸收的多租户设计点**：租户套餐（每店开关功能包）/租户到期禁用/数据权限分层/二级域名分租户；
- **我们的底子**：连锁两层模型+数据隔离（商家端大批已建+互盲实证过）就是多租户的种子——建议产品侧出专项评估「store→tenant 抽象」（什么时候把「店」升维成「租户」），不赶现在；
- **PM 盯**：今后每批任务书两问闸加一问——「这件为三店写死了吗？」（写死=返工雷）。

## 六、一句话总结
**立干**：screenshot-to-code 试一屏+promptfoo 建评测基线+AGENTS.md 格式对齐（三件零基建）；**中期包**：GlitchTip/Uptime Kuma/Umami+Langfuse 同上 VPS；**专项**：Novu 随触达批、多租户抽象随规模化专项。**不碰**：Java 系 SaaS 脚手架。
