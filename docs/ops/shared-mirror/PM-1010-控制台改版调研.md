# PM-09 · 控制台（开发者管理端）改版调研：病根+范本+方案（2026-10-10，老板令：PM 亲自调研）

> 老板抓：「整个这一页都不知道是什么」——图 2 实证：控制台=工程师参数表（cfghelp:xxx 键值堆一屏）。
> **🔧范围更正（10-10 老板指正）**：开发者管理端=**商家端侧边栏底部的附属子界面**（非独立端口；底部还重复挂着规则配置/文案端口/槽位端口三入口）。改版范围=该子界面+重复入口归并，商家端主体不动。

## 一、病根（举一反三）
**按「数据怎么存」组织，不按「老板要办什么事」组织**。参数表是数据库的投影，不是控制台。同行没有任何一家把键值清单当首页。

**🔧更正两件（10-10 老板指正）**：①问题清单 #1 撤销——开发者子界面=**控制客户端的管理界面**，不需要今日经营台（经营数据归驾驶舱，不在这层）；②画布真缺口两条：**权益墙改不了**（权益项是数据驱动，文案键只能改标题=改不动内容）+**画布只控三屏**（产品侧任务书自定「首吃三屏」收窄了老板意图——老板要**全屏全内容可控**）→画布全屏批立项候选。

## 二、范本（全网实证）
1. **Shopify Admin**（全球商家后台标杆）：侧边栏=**业务对象**（订单/产品/客户/分析/营销/折扣）+主页=**任务提醒**（未付款订单等着办的事）+顶栏**全局搜索**（Cmd+K 直达任何设置）——任务导向+对象导航+搜索直达三件套；
2. **有赞**：开店向导=里程碑闯关（上架商品→完善信息→配支付→装修店铺），完成一步打钩庆祝——新手引导件；
3. 开源模板（vue-element-admin 88k★/Ant Design Pro/React Admin 25k★）——**注意：我们缺的不是 UI 皮，是信息架构（IA）**；模板件只当组件参照，不解决组织问题。

## 三、方案（控制台改版批建议四刀）
1. **首页改「今日经营台」**：今日营收+待办（待审批/库存预警/差评/挂单）+快捷入口——老板打开第一眼=今天要办什么；
2. **侧边栏改按业务对象分**（人/货/场/钱）：客户（会员+宠物档案）／服务与商品／预约与订单／营销／门店与员工／报表／设置；
3. **现有端口件一个不删**，全收进「设置」深处+顶部全局搜索直达（搜「提成」直达那条 cfghelp）——工程师视图降级为搜索可达的高级层，不再是门面；
4. **画布端口=「装修店铺」场景位**（照有赞向导位），文案/槽位/参数字典=「设置-高级」。

## 四、排产建议
控制台改版批插冲刺清单**支付批之后**（与首页改版批分开：一个是客户端首页，一个是后台首页）。UI 参照=Tabler/AC 风格件（组件级），IA 照 Shopify。
