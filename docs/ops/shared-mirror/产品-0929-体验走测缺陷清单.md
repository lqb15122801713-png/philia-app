## 〇、病根（一句话）

我们的「返回键」多处写死**固定目标**（不管用户从哪来），世界级模型（Android 官方原则）：**Back=时间序回退（回到来处），Up=层级回退；多入口页的 Up 必须与 Back 一致**。我们的 BackButton/PageHeader 组件本已具备「有栈走 -1、无栈（直访）兜底父页」能力，是几处页面用固定 to= 绕过了它。

## 五、调研结论（世界级怎么做的）

1. **Back=时间序、Up=层级**（Android 官方）：多入口页的 Up 必须与 Back 一致——「回到 referring screen」；我们的病根恰是反着来。
2. **可见 Back 避免死胡同**（2025-2026 行业清单一致项）：每个屏都要能答出「我从哪来、回哪去」；当前位置永远可见。
3. **直达/深链补全向上路径**：直访深页时，返回应能一路回首页再退出（Gmail 模型）——我们的「无栈兜底父页」与此一致，保留。
4. **沉浸式任务页（LIVE/支付类）返回=退出来处**，不压新层级——全程页死循环的直接违反点。

**入规建议（老板拍板）**：「返回=时间序回退」写入施工口径（固定 to= 仅许交易成功页双出口类明示场景）+QA 用例+复核抽点三处。
