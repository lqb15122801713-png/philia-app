# K ｜ 星巴克/瑞幸式「简洁型首页」解剖报告

> 命题：Philia 首页改版 V2 —— 顶层 hero + 会员身份条 + 双服务大卡 + 回馈金行不动，下方内容区要「内容多而不乱」。
> 方法：一手拆解文章 + 改版复盘文，逐层解剖星巴克中国 APP、瑞幸咖啡 APP/小程序，辅证麦当劳 / 喜茶 / 小米商城 / vivo 官网 APP。

---

## 一、两个主对标：逐层解剖表

### 1. 星巴克中国 APP（2022「近年最大一次升级」版，结构沿用至今）

| 层（自上而下） | 内容 | 为什么在这 | 密度 |
|---|---|---|---|
| 1. 顶部核心行动区 | 三大点单功能：啡快（自提）、专星送（外送）、咖啡生活馆（零售），**同一行紧凑展示**；下滑时三者始终置顶 | 90% 的打开意图是点单，高频动作必须在第一屏且无歧义；置顶保证任何时候 1 步可达 | 极低：一行三入口，无文案轰炸 |
| 2. 次级点单区 | 「多人团餐」「送心意」「外卖拼单」首次被单独拎上首页 | 次一级但有增长诉求的场景（团购/送礼），放在主行动之下——**第二屏的「第二行动」**，不与主行动抢视觉 | 低：一行小卡，纯功能无促销色 |
| 3. 内容区 | 「星闻」信息流（咖啡豆故事、咖啡文化图文/视频），放在**首页信息流最后** | 内容负责逛和时长，不负责首屏转化；放在最底，想看的人滑到，不看的人无感 | 中：卡片流，版式统一 |
| 4. 互动/会员区 | 拆出到底部 Tab「星会员」：星动市集、神奇的豆子（咖啡护照）、门店探索（探店打卡） | 互动深度内容**不占首页面积**，用 Tab 承载；首页只留「联结感」不留「玩法列表」 | 首页密度 = 0，全部转移 |
| 5. 系统件 | 消息挪到首页右上角小图标；底 Tab 新增「订单」聚合所有订单 | 高频状态（订单）进 Tab，低频通知（消息）收成角标——**把「查」和「办」分开** | 极低 |

要点：首页 = 「点单 + 逛内容」两件事。会员、积分、商城、活动全部有归宿（Tab/二级页），**首页不是业务的陈列室，是高频动作的加速器**。

### 2. 瑞幸咖啡 APP（2021 版场景化设计拆解，结构稳定至今）

| 层（自上而下） | 内容 | 为什么在这 | 密度 |
|---|---|---|---|
| 1. 顶部信息栏 | 门店名 + 距离 + 「自提/外送」大开关 | 点单前置条件（在哪取）一次解决；开关大、对比强，避免跳页 | 低：两行信息 |
| 2. 高频瓷片区 | 「现在下单」+「领券中心」两个大瓷片并列 | 下单是最高频动作；瑞幸用户下单前必先领券，**两个强相关动作绑在一起**，路径最短 | 低：两个大卡，几乎无其他元素 |
| 3. 促销广告区 | 单条横幅/banner（新人优惠专享、当季活动） | 转化件，但**同一时间只推一个活动**，附购买任务 | 低-中：一屏一条，Z 字错落卡 |
| 4. 商品/内容列表区 | 卡片式商品流：灰底 + 白卡，配图统一「纯色低饱和底 + 产品图」，Z 字错落排版 | 「逛」的需求交给列表，但用**版式绝对统一**压住复杂度；错落防眼动疲劳 | 中：无限流，但每张卡信息结构完全一致 |
| 5. 我的/会员 | 深品牌色头图 + 会员卡模块 + 常购清单 + 下拉箭头折叠低频功能 | 品牌感和复购（常购）放「我的」，**次要功能用下拉箭头隐藏而非删除** | 首页密度 = 0 |

要点：瑞幸首页其实有 5 类内容（下单、领券、活动、商品流、资讯播报条），但用户感知只有「两个大按钮 + 一条横幅 + 一个流」。**多藏在统一容器里，乱被版式纪律消解**。

## 二、辅证：同思路的「顶部主行动 + 下方内容」首页

- **麦当劳 APP**：首屏两个巨型按钮「麦乐送 / 到店取餐」，按钮图案拼成一幅画；广告海报**平铺在最底层当背景**，会员卡框叠其上，点餐按钮在最上——用**图层叠加**省空间，广告不单独占位、不产生心理疲劳。全界面统一圆角。[CSDN《UI竟在我身边#2：麦当劳APP》](https://blog.csdn.net/weixin_62428841/article/details/122646097 "citation")
- **麦当劳小程序分层运营**：新用户首屏只推「新人福利」，老会员首屏只推「会员卡内优惠套餐」——**同一楼层，千人千面，密度恒定**。[人人都是产品经理《6000字拆解：麦当劳的私域》](https://www.woshipm.com/operate/4975426.html "citation")
- **喜茶小程序**：banner 用 3:2 近黄金比例、纯直角设计语言、不对称安全边距（左 20 / 右 0）制造记忆点；点单页新品推广位第三个广告位「露半个」暗示可左滑——**用出血和比例代替更多楼层**。反面教训也被点明：标签颜色一多、图标一多就乱，「尽可能少去表现」。[站酷《喜茶小程序产品设计体验分析》](https://m.zcool.com.cn/article/ZMTU1MDA2OA==.html "citation")
- **小米商城首页改版**：一拖三瓷片区 → 一拖四，核心动作是「去营销化」——四个卡位**最多只允许一个营销标签**（都加 = 没有突出）；「宽松一定打败紧凑」；字号不许大过板块标题（常态模块不许出现「不冷静的字号」）；间距遵循五分原则。[人人都是产品经理《小米商城APP首页全新升级》](https://www.woshipm.com/pd/5850776.html "citation")
- **vivo 官网 APP 首页改版「至简」**：全部楼层**收敛为 3 类容器**（广告容器 / 产品容器 / 内容容器），产品文案限制在 3 阶之内，社区楼层只露出「标题/来源/互动」三要素——容器少 = 心智少。[优设网《vivo官网APP首页改版设计过程复盘》](https://www.uisdc.com/vivo-app-redesign "citation")
- **江苏移动 APP 反面教材 → 解法**：首页原本 10 个楼层，改版砍到 4 个固定模块 + 其余用户自定义。[站酷《江苏移动掌厅改版小记》](https://m.zcool.com.cn/article/ZNzg5ODYw.html "citation")

## 三、「多而不乱」手法清单（可直接抄）

1. **顶部主行动区恒定、极少、置顶**：高频动作 ≤ 3 个并排放一行（星巴克三大点单 / 麦当劳双按钮 / 瑞幸下单+领券），下滑置顶，永远 1 步可达。
2. **一屏一焦点**：每屏只允许一个视觉重心；促销/转化件同一时间只出现 1 个（瑞幸单条横幅；小米「四卡最多一个标签」）。
3. **容器收敛**：全部内容塞进 ≤ 3–4 种容器（vivo 三容器），容器版式绝对统一（瑞幸灰底白卡、配图统一纯色底）。
4. **卡片节奏：大小卡交替 + Z 字错落**：大卡讲一件事，小卡讲一类事；错落排版防浏览疲劳，但**信息结构不变**。
5. **用留白分隔，不用分割线/色块堆**：楼层间靠间距呼吸（小米五分原则：内边距关系按 1/2 递减），「宽松打败紧凑」。
6. **转化件的克制**：广告当背景（麦当劳图层叠加）、活动收横幅、营销标签限额；转化件**融进主路径**而不是另起楼层。
7. **层级转移而非堆叠**：会员、互动、玩法 → 底部 Tab 或二级页（星巴克星会员 Tab）；次要功能折叠（瑞幸下拉箭头），**首页不是业务清单**。
8. **状态与动作分家**：「查」（订单/消息/通知）收成 Tab 或角标；「办」（预约/下单/领券）才配占大卡。
9. **千人千面压密度**：同一楼层按用户状态换内容（麦当劳新客/老会员首屏不同），**密度不增、相关性增**。
10. **出血暗示续读**：横滑列表故意露半个（喜茶第三个广告位），告诉用户后面还有，不用加「更多」楼层。

## 四、落到 Philia 的 V2 结构建议

### 4.1 不动的顶层（按老板要求）

- Hero 大图（品牌/情绪）
- 会员身份条（等级 + 回馈金入口合并为一行）
- 双服务大卡：预约洗澡美容 / 预约寄养（= 星巴克的三大点单 / 瑞幸的下单瓷片，**这是 Philia 的「下单+领券」**）
- 回馈金账本行、一键再约、毛孩子入口（现状保留，作为「状态件」，形态瘦身为一行）

### 4.2 下方内容区：4 层封顶，每层一种容器

| 层 | 内容 | 形态 | 密度与规则 |
|---|---|---|---|
| C1 进行中/再约状态条 | 最近预约状态 + 一键再约 | 一条横条（非楼层） | 贴在双大卡正下方，是主行动的延伸，**不是独立楼层** |
| C2 案例流（真实服务案例/客户评价/宠物故事） | 卡片流：灰底白卡、统一版式（一张图 + 一句话 + 宠物名） | 无限流但**结构恒定**，可 Z 字错落 | 首页的「逛」，放最前——服务内容化，建立信任；抄瑞幸列表区 |
| C3 活动（当季活动/会员回馈金活动） | **单条横幅**，同一时间只推 1 个 | 一层 | 转化件的克制：不并排、不堆叠；千人千面（新客推首单礼，老客推回馈金玩法） |
| C4 商品（商城精选） | 横滑小卡，一屏 2.5 个（露半个暗示续读） | 一层，最多展示 4–6 个 | 「更多」进二级页；不带促销标签雨 |
| C5 回馈金账本 | 一行账本摘要（余额 + 最近一笔变动），点击进明细页 | 一行，非卡片 | 账本**只给状态不给表格**，明细永远在一层之下 |

顺序逻辑：状态（C1）→ 信任/逛（C2）→ 转化（C3）→ 货架（C4）→ 资产（C5）。内容可以很多（案例流无限），但楼层只有 5 种容器、每屏一个焦点。

### 4.3 明确「什么不出现」（防 58 同城病的红线）

1. **不出现金刚区/图标宫格**：功能入口超过 4 个一律进 Tab 或「我的」，首页不放第二组入口阵列。
2. **不出现第二个促销件**：活动横幅全首页只有 1 条；任何「限时」「抢购」「满减」标签不得在案例流和商品卡上同时出现（小米规则：都加 = 没加）。
3. **不出现弹窗矩阵 + 悬浮球 + 跑马灯通知的组合**；消息只进右上角角标。
4. **不出现文字超过两行的卡片**；文案限制在 3 阶之内（标题/一句卖点/价格）。
5. **不出现「积分/等级/勋章/任务中心」类会员玩法楼层**——全部收进身份条后的二级页（星巴克「星会员」Tab 思路）。
6. **不出现两类内容混排**：案例流就是案例流，商品流就是商品流，不做「猜你喜欢」大杂烩。
7. **不新增楼层解决业务诉求**：新业务要么替换 C3 横幅，要么进 Tab，要么不做。楼层数恒定在 5。

---

## 五、一句话结论

- 星巴克/瑞幸的结构：**「一行高频动作置顶 + 一条横幅 + 一个版式绝对统一的内容流 + 其余全部收进 Tab」**。
- Philia V2：**「hero+双大卡+身份条不动，下方只做 5 层——状态条、统一版式案例流、单条活动横幅、横滑商品、一行账本，金刚区和促销雨永远不上首页」**。
