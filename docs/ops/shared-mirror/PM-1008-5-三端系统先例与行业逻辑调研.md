# PM-05 · 三端系统先例与行业逻辑调研（2026-10-08，老板问：有没有先例/行业逻辑/成功案例）

## 一、先例：开源+商业都一大片（三端系统=成熟品类）

**开源先例（GitHub 实证）：**
- **mms**（zhaojiannet/mms）：Go 版多租户会员管理 SaaS，**明确适配宠物行业**——收银台（多卡组合扣费）/会员档案/预约/挂账/报表/三级权限/**多租户 PostgreSQL 行级隔离**——和我们连锁数据隔离同族思路，可作规模化段参照；
- **fuint**：Java 会员营销多租户 SaaS（会员卡券/储值/积分/预约 O2O/消息提醒）；
- **ICEPOS**：国内少数全开源收银系统（多门店/离线/员工交接班/微信支付宝）；
- store-system-uniapp：连锁门店小程序进销存。

**商业先例（市场验证过的刚需组合）**：乔拓云/纳客/银豹/中仑——宠物店「收银+会员+预约+寄养」四件套是标准答案；连锁版=三店以上定制是行业共识（总部报表+统一会员账）。

## 二、行业逻辑（多源一致的演进路径）

单店 SaaS 跑顺 → 多店连锁（数据汇总+会员通用）→ 总部数据中台。**我们直接按连锁两层+端口化+全国规模化起步=跳级，但方向与市场演进完全一致**。行业金句（博纳 13 年定制经验）：「会员卡跨店通用、通存通兑这类规则，一般只有定制版做得到」——正是我们在建的东西。

## 三、AI 团队开发的成功案例（对照我们）

- **腾讯云实证**：WorkBuddy（主控）+Qclaw（审查）双 agent 7 天交付生产级功能——「建查分离」同款，我们是七窗加强版；
- **飞书大赛案例**：东风奕派/雅迪等（提效 16 倍/协同 +40%）——均为工作流型 agent，不是全流程建产品；
- **8 周落地复盘**（人人都是产品经理）：「技术 Demo 只完成 30%，业务敢用才是战场」+权限矩阵要业务书面确认+上线前 3 天现场陪跑——**与我们「切换日演练/老板终审/门店傻瓜版清单」同思路**；
- 结论：成功案例多为单功能/工作流级；**我们这种「AI 团队从零建三端生产系统」在公开案例里属于前沿**——半成品感不是因为走错了，是因为没人趟过的路没有参照物。

## 四、可偷的三件
1. mms 的 RLS 行级多租户隔离——规模化段（store→tenant）的参照实现；
2. 行业提醒：「数据可导出可迁移」=反绑死条款，咱们端口化+台账导出照此验收；
3. 「换系统挑淡季、先理流程图再谈系统」——门店上线节奏参照。
