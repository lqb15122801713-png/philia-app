## 一、省了什么（真收益）

1. **用户旅程强制独立可测**：每条 User Story 必须「单独交付也是 MVP」+Given-When-Then 验收场景——比咱们任务书的散文式范围描述更防漏（今天老板撞的三个雷，spec 这层就会提前显形）；
2. **成功标准可量化**（SC-001 漏发=缺陷/重复率 0%/≤3 步成交）——验收尺前置到规格阶段，比我们「复核时才发现没尺子」强；
3. **Constitution Check 是真好用**：军规装进去后，plan 必须逐条对照过闸（能调/冻结墙/涉钱/建查分离全被点名）——军规从「靠自觉」变「强制对照表」；
4. clarify 机制（不明处最多标 3 个候裁）与咱「开口项候老板裁」同构。

## 二、卡在哪（真成本）

1. **Kimi 集成认不出本机 Kimi Code**（init 检测 kimi CLI 失败，须 --ignore-agent-tools 绕过）——官方支持是有的但检测脆；
2. **「规格不许写实现细节」与咱工艺有张力**：Spec Kit 的 spec 刻意不写技术，plan 才写；我军任务书要求「哪个文件哪个键」级指引（防施工漂移）。spec→plan 的跳跃仍需人肉，省不掉；
3. **与既有冻结墙工艺重复**：开口项/两问闸/冻结版签署我们已有且更硬（老板签字级），Spec Kit 的 clarify 反而弱（最多 3 个）；
4. **implement 环节与 A 窗片序工艺不兼容**：它的 tasks 是平铺清单，没有我们的片序/卷宗/回执/闸门/树零差异合部链——要入规得写适配层，工程不小；
5. skills 要逐窗装（A/B/QA 各窗各挂一遍）。

## 三、值不值得入规（结论）

**借魂不借壳：不建议入规工具本体，建议把三件魂吸进任务书模板 V2**——

1. 任务书加「用户旅程节」：每条旅程 Given-When-Then 验收场景（防漏神器，今天就缺它）；
2. 任务书加「成功标准节」：可量化验收尺前置（复核第八步人走查照尺打）；
3. 宪法闸保留在 speckit-lab 当对照表：任务书起草时我逐条自检对照（零工具成本）。

**不入规的理由**：工具链收益=结构化骨架，成本=五处卡点+适配层+A 窗工艺改造；骨架我们用模板就吸走了，壳不值。下一批任务书起草我直接上 V2 模板实证，效果好再议要不要回头装壳。
