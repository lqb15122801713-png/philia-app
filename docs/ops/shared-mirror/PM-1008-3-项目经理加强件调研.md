# PM-04 · 项目经理加强件调研（2026-10-08 第三圈，老板极致授权）

> 老板令：「GitHub 上没有项目经理的加强技能包和 MCP 或者 skill harness 吗？去找一圈。」
> 三圈扫描：任务管理 MCP／PM 技能包（SKILL.md 制）／skill harness／跨会话记忆。按 PM 窗真实痛点映射（队列依赖账/裁定台账/发令双齐/换会话零损耗）。

## 一、Task Master AI（eyaltoledano/claude-task-master，MCP，热门）——「AI 项目经理」
- **是什么**：PRD→自动拆成带依赖关系的结构化任务→逐条执行追踪→「下一棒该干什么」推荐；MCP 协议即装，多模型可配（DeepSeek 档可跑）；
- **对 PM 窗什么用**：12 表队列+前后性依赖图的机械化——它管「依赖图+下一棒推荐」，正好是我手工时序账的算盘；
- **边界（诚实）**：它是任务计算器，不是裁定账本——老板裁定/豁免/双签语境它不懂，台账主权仍在我；
- **建议**：PM 窗试点——把当前队列喂进去跑一周对照，评估「依赖推导」比我手工账强不强；**不强就当算盘留着用**。

## 二、PM 技能包四件（SKILL.md 制，免费开源）——角色卡③的技能芯片
开源界 PM 技能已成气候（deanpeters 70+ 件包/Digidai 6 域 30 框架包/prodmgmt.world 免费四件）。挑**最对口的四件**：
| 技能 | 干什么 | 对 PM 窗什么用 |
|---|---|---|
| **decision-log** | 决策日志结构化（背景/选项/落槌/追溯） | **裁定台账的工业化**——CJ 编号件的生成+检索机械化 |
| **prd-review** | 任务书/PRD 审查清单 | 产品侧草案到我手先过一遍机器尺再呈老板 |
| **stakeholder-update** | 干系人同步件生成 | 同频卡/状态广播的模板化 |
| **interview-synthesis** | 用户反馈综合（证据钉死：每条结论必引原话） | 下午真机走测客户反馈表的回收分级 |
- **落地**：SKILL.md 是通用格式——搬进 PM 技能目录或用 plugin-builder 转成 Kimi 插件，半天件；
- **建议**：四件全搬，先搬 decision-log。

## 三、skill harness（参照件，读思想不装机）
- **obra/superpowers**（MIT）：最出名的 harness 方法论包（brainstorm→plan→TDD→subagent→review 全链）——**思想参照**：它的「每步带完成判据、不许跳步」与我们闸门族同源；不装（我们是 Kimi Work 体系，角色卡+任务卡已是我们的 harness）；
- **taches-cc-resources**：含 skill-auditor 元技能（审 skill 的 skill）——promptfoo 基线的同款思路印证。

## 四、跨会话记忆（评估件，不急换）
- 我们「看板封存+点名口令读档即恢复」=文件制记忆，零依赖已跑稳——开源对照件：**Memoria**（矩阵起源 2026 开源，「Git for Memory」记忆版本化可回滚，治「记忆写坏回不去」）/agentmemory（行为记忆自动捕获+知识图谱，95.2% 召回）；
- **建议**：出对照一页评估（封存制 vs Memoria），**跑稳不动**——封存制有老板裁定语境，机器记忆替代不了裁定台账；只在「各窗技术决策历史自动捕获」这一点上有增量（A/B 窗适用）。

## 五、一句话总结
**立干**：Task Master 试点（当算盘）+PM 技能四件（先搬 decision-log）——PM 窗自我加强两件；**评估**：Memoria 对照封存制；**不碰**：商业 PM OS、harness 框架（读思想即可）。
