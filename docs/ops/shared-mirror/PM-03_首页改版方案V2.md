# PM-03 V2｜Philia 客户端首页改版方案（终审·修订版）

> 产出：PM 方案制作手 ｜ 依据：K 路调研（星巴克/瑞幸式简洁型首页解剖）、J 路调研（内容生产与转化，SOP 沿用）
> V1 打回原因：楼层太多太满，像 58 同城。
> **V2 唯一方向（老板口径）：简洁简单，但内容不简单。顶层服务大卡（hero 大图＋会员身份条＋预约洗澡美容/预约寄养双大卡＋回馈金账本行＋一键再约＋我的毛孩子）全部不动；下方内容区可以有很多内容和排布——星巴克/瑞幸式。**

**一句话版：hero＋身份条＋双大卡＋状态件行不动，下方只做 5 层——①再约状态条、②统一版式案例流、③单条活动横幅、④横滑商品、⑤一行账本；金刚区和促销雨永远不上首页。**

---

## 总原则（星瑞式结构）

星巴克/瑞幸验证过的简洁首页公式：**「一行高频动作置顶 ＋ 一条横幅 ＋ 一个版式绝对统一的内容流 ＋ 其余全部收进 Tab」**。瑞幸首页其实有 5 类内容，但用户感知只有「两个大按钮＋一条横幅＋一个流」——**多藏在统一容器里，乱被版式纪律消解**。

落到 Philia 的三条铁律：

1. **顶层全不动**——hero、身份条、双服务大卡、状态件行（回馈金账本行/一键再约/我的毛孩子）是 Philia 的「下单+领券」，现状保留。
2. **内容区 5 层封顶，每层一种容器**——顺序逻辑：状态（①）→ 信任/逛（②）→ 转化（③）→ 货架（④）→ 资产（⑤）。内容可以很多（案例流无限），但楼层只有 5 种容器、每屏一个焦点。
3. **凡内容皆留口**——所有层的文案、图片、排序、显隐规则全部入后台槽位/文案端口，不写死。

**归位说明（避免与顶层重复占位）**：①再约状态条是顶部「一键再约」的状态化归位——合并「最近预约状态」，贴双大卡正下方，首页再约入口只此一处；⑤一行账本是顶部「回馈金账本行」的规范化形态——一行摘要（余额＋最近一笔），明细永远在一层之下。老板口径「全部不动」指功能与入口不消失，①⑤即这两个件的不动形态。

## 一、顶层不动区（现状保留，仅列档；图例：fig1-首页楼层结构V2.png 上半）

| 件 | 内容 | 数据来源 | 转化目标 | 后台可控口径 |
|---|---|---|---|---|
| **Hero 大图区** | 品牌/情绪大图，节庆可整套换肤 | 后台素材库 | 品牌感，无硬转化 | 图与文案入**素材槽位**；节庆换肤包入**节庆配置** |
| **会员身份条** | 等级徽章＋回馈金入口合并一行（「萤火会员 · 回馈金 ¥126.5 ›」） | 会员档案＋回馈金账本 | 会员身份可见＋账本入口 | 文案模板入**文案端口**（金额变量位）；显隐入**开关槽位** |
| **双服务大卡** | 预约洗澡美容 / 预约寄养，两卡并排＝星巴克的三大点单、瑞幸的下单瓷片 | 静态配置 | **预约直达，首页第一转化动作** | 卡名/图/跳转入**大卡槽位**；全首页仅此一组行动大卡（系统硬约束） |
| **状态件行** | 回馈金账本行 · 一键再约 · 我的毛孩子，三入口瘦身为一行 | 账本/订单/宠物档案 | 状态件：查的入口，不抢视觉 | 三入口显隐与排序入**状态件槽位**；文案入**文案端口** |

## 二、内容区五层（V2 全部新增/归位；图例：fig1 下半）

### ① 再约状态条｜主行动延伸层（贴双大卡正下方，非独立楼层）

| 项 | 说明 |
|---|---|
| **什么件** | 一条横条（不是卡片、不是楼层）：左「最近预约状态」，右「一键再约 ›」 |
| **什么内容** | 进行中：「美容进行中 · 预计 17:30 完成」；已完成/无单：「上次洗护 3 天前 · 一键再约」。承接顶部一键再约归位 |
| **数据来源** | 预约/订单系统（最近一单状态）；再约＝上次服务单一键复制下单 |
| **转化目标** | 复购直达（再约一键完成）＋ 履约透明（状态安心）。手法 8：**状态与动作分家**——这条管「查+复购」，双大卡管「办新单」 |
| **后台可控口径** | 状态文案模板入**文案端口**；显隐规则（有进行中预约或近 30 天有单才显示）入**后台配置**；归位规则（顶部再约按钮并入本条）上线时一次切换 |

### ② 统一版式案例流｜信任与时长层（无限流，纯内容）

| 项 | 说明 |
|---|---|
| **什么件** | 卡片流：纸白底＋白卡，**版式绝对统一＝一张图＋一句话＋宠物名**；可大小卡交替、Z 字错落防疲劳，但信息结构恒定 |
| **什么内容** | 门店真实服务案例/客户评价/宠物故事，素材来自七节点照片体系（生产链见第四章 SOP 指针）。**纯内容，零硬转化**——V1 的流内转化卡全部撤出（负面清单 6：两类内容不混排） |
| **数据来源** | 案例库（授权等级≥3、机审+人审通过；质量 A 级优先入流）；排序按时间/质量/宠物品种相关性 |
| **转化目标** | 种草、信任、停留时长——首页的「逛」。抄瑞幸列表区：复杂度交给无限流，版式纪律压住乱 |
| **后台可控口径** | 卡版式模板入**组件配置**并锁死（一图一句一宠物名，文字≤两行，系统硬约束）；排序权重入**推荐策略槽位**；上新节奏（每店日 1–3 条）入**发布配置**。手法 3 容器收敛、手法 4 大小卡交替＋Z 字错落、手法 5 留白分隔、手法 10 出血续读 |

### ③ 单条活动横幅｜全首页唯一促销件

| 项 | 说明 |
|---|---|
| **什么件** | 单条横幅，**同一时间全首页只有这 1 个促销件**（瑞幸单条横幅；小米规则：四卡最多一个标签，都加＝没加） |
| **什么内容** | 当季活动/会员回馈金活动；**千人千面**：新客推首单礼，老客推回馈金玩法（麦当劳分层运营：同一楼层按用户状态换内容，密度不增、相关性增） |
| **数据来源** | 活动管理（总部下推 S 级/门店自配）；用户分群（新客/老客/会员档位） |
| **转化目标** | 活动报名/首单/到店——内容区唯一硬转化出口。节庆换装仅限此横幅＋hero 换肤，不新增楼层 |
| **后台可控口径** | 横幅入 **A5 运营槽位·单条模式**（同时间上线上限＝1，系统硬约束）；图文入**文案端口**；人群定向规则入**后台配置**。手法 2 一屏一焦点、手法 6 转化克制、手法 9 千人千面 |

### ④ 横滑商品｜货架层（一层，最多 4–6 个）

| 项 | 说明 |
|---|---|
| **什么件** | 横滑小卡，**一屏 2.5 个**（第三个露半个暗示续读，喜茶手法——用出血代替「更多」楼层）；「更多」进商城二级页 |
| **什么内容** | 商城精选 SKU；卡面只有三阶：图/名称/价格；**不带促销标签雨**（全卡最多一个营销标签） |
| **数据来源** | 商城商品池（精选逻辑与排序后台可配） |
| **转化目标** | 商品下单＋商城二级页引流。商城「在码」期间首页只给这一层横滑，不做货架楼层 |
| **后台可控口径** | 选品与排序入**商品配置槽位**；卡版式锁死（三阶文案）入**组件配置**；标签限额（≤1 个/屏）入**系统硬约束**。手法 10 出血、手法 6 克制、手法 3 容器收敛 |

### ⑤ 一行账本｜资产收尾层（一行，非卡片）

| 项 | 说明 |
|---|---|
| **什么件** | 一行账本摘要（不是卡片、不进表）：「回馈金 ¥126.5 · 昨日洗护返 ¥12 ›」，点击进明细页 |
| **什么内容** | 回馈金余额＋最近一笔变动；**只给状态不给表格**，明细永远在一层之下。承接顶部回馈金账本行的规范化形态 |
| **数据来源** | 回馈金账本系统 |
| **转化目标** | 资产可见 → 复购与续费的「值」感（山姆公式）；收尾层让用户滑到底时看到「自己的钱在变多」 |
| **后台可控口径** | 摘要文案模板入**文案端口**（金额/变动为变量位）；显隐规则（余额＞0 才显示）入**后台配置**。手法 8 状态与动作分家、手法 5 留白收尾 |

## 三、「多而不乱」十条手法 → 落层对照表

| # | 手法 | 落在哪 |
|---|---|---|
| 1 | 顶部主行动恒定、≤3 个、置顶 | 顶层双服务大卡（不动区） |
| 2 | 一屏一焦点，促销件同一时间只 1 个 | ③ 单条活动横幅（硬约束） |
| 3 | 容器收敛 ≤3–4 种，版式绝对统一 | 内容区只有 5 种容器：条/案例卡/横幅/商品小卡/账本行 |
| 4 | 大小卡交替＋Z 字错落，信息结构不变 | ② 案例流 |
| 5 | 用留白分隔，不用分割线/色块堆 | 全内容区层间距纪律（五分原则） |
| 6 | 转化件克制：融进主路径，不另起楼层 | ③ 横幅是唯一促销件；④ 无标签雨 |
| 7 | 层级转移：会员玩法/互动收 Tab 或二级页 | 负面清单 5；底 Tab 承载 |
| 8 | 状态与动作分家：查收角标/行，办才配大卡 | ① 状态条、⑤ 账本行 vs 双大卡 |
| 9 | 千人千面压密度：同层换内容，密度不增 | ③ 新客/老客分群；② 品种相关性排序 |
| 10 | 出血暗示续读 | ④ 横滑露半个；② 无限流 |

## 四、负面清单 7 条（防 58 同城病，首页红线，永不上首页）

1. **永不上金刚区/图标宫格**——功能入口超过 4 个一律进 Tab 或「我的」，首页不放第二组入口阵列。
2. **永不上第二个促销件**——活动横幅全首页只有 1 条；「限时/抢购/满减」标签不得同时出现在案例流和商品卡上。
3. **永不上弹窗矩阵＋悬浮球＋跑马灯的组合**——消息只进右上角角标。
4. **永不上文字超过两行的卡片**——文案限制在 3 阶之内（标题/一句卖点/价格）。
5. **永不上「积分/等级/勋章/任务中心」类会员玩法楼层**——全部收进身份条后的二级页（星巴克「星会员」Tab 思路）。
6. **永不上两类内容混排**——案例流就是案例流，商品流就是商品流，不做「猜你喜欢」大杂烩。
7. **永不新增楼层解决业务诉求**——新业务要么替换 ③ 横幅，要么进 Tab，要么不做；楼层数恒定在 5。

## 五、内容生产 SOP（沿用 J 调研，不重写）

案例流②的供稿链完全沿用 V1 方案第三章（J 路调研成果），此处只留指针：

- **生产链五环**：员工端七节点拍照（不加 KPI、零增量）→ 系统按授权等级过滤（≥3 级才进候选池）→ 商家端机审＋人审（人脸/车牌/门牌打码，质量 A/B/C 分级，A 级优先入流）→ 门店官方号统一发布 → 客户端案例流。
- **五级授权表**：仅存档 / 发给我 / 社交媒体 / 官网与付费广告 / 有人入镜；沉默=拒绝、拒绝零代价、授权不随宠物转移。
- **隐私红线六条**：公司账号 only、不具名、不打位置标签、医疗窘迫零发布、机审前置先审后发、撤回优先不争辩。
- 详见 [PM-03_首页改版方案.md](PM-03_首页改版方案.md) 第三章、fig3-内容生产链.png。
- **V2 差异仅一处**：发布模板从「双列瀑布卡」改为「统一版式卡」（一张图＋一句话＋宠物名，文字≤两行），商家端发布器按此模板校验。

## 六、实施建议（三期）

| 期 | 做什么 | 为什么先做/后做 |
|---|---|---|
| **一期：归位** | 顶层四组件保持不动；一键再约归位为 ① 状态条、回馈金账本行归位为 ⑤ 一行账本；② 统一版式案例流上线（含发布器模板改造）；SOP 沿用现行 | 老板痛点是「乱」：先做减法与归位，零新增业务风险；案例流是「内容不简单」的主体，供稿链已在一期验证过 |
| **二期：上转化** | ③ 单条活动横幅（A5 单条模式＋千人千面分群）＋ ④ 横滑商品（商城精选池） | 案例流供给稳定后再放唯一促销件；商城「在码」收尾后接横滑商品层 |
| **三期：精运营** | 节庆换装（hero＋③ 联动）、案例流推荐策略调优（品种相关性）、⑤ 账本摘要文案 A/B | 锦上添花项，依赖前两期流量与数据 |

**验收口径（每期上线前自查）**：结构与 fig1 V2 一致（顶层四件未动、内容区正好 5 层）；负面清单 7 条逐条过一遍（无金刚区、无第二促销件、无弹窗矩阵、无超两行卡片、无会员玩法楼层、无混排、无新增楼层）；每张已发布案例可查到授权等级与审核日志。
