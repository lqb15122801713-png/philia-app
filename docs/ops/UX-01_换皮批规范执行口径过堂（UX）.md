## 一、F2 柠檬黄 #FDC830 = 开工必查项（实证）

**总根在 `packages/shared/src/tokens.ts`（4 处）**：`primary: '#FDC830'` ×2（明/暗两套色板）、`philia: 'linear-gradient(135deg, #FDC830 → #7FD8BE)'` ×1、VI 注释 ×1（口径注释本身已过期，须随码改）。

**三端引用/硬编码面（12 文件）**：apps/customer（index.css）、apps/customer-mini（app.css）、apps/staff（index.css / ExecutePage / scan-QrScanner / scan-ManualCodeInput）、apps/merchant（index.css / MonitorHubPage / dashboard-TodoSection / cashier-PickPanel / cashier-PaySheet / cashier-OfflineBar）。

**处置口径**：
1. 变量级替换，不许逐文件手改——`tokens.ts` 的 `primary` 改挂 v2.0 点睛 token（`--gold #F2DFA6`），下游引用自动归位；硬编码 12 文件逐处 grep 清零；
2. `philia` 渐变（亮黄→薄荷绿）**整体退役**——亮黄与深绿系双禁（CJ-0921-10），渐变按钮本就是反廉价黑名单件；
3. 主行动色归位：客户端=深棕主钮（定稿口径）；员工端/商家端=淡黄写死「此刻要做的」（方向稿裁定语义，随两端定稿语言包落地）；
4. 暖阳橙 #D97B4A 复 grep=0（已清，保持）；
5. **闸门：换皮批交付前 `FDC830` 全域 grep = 0，缺一像素不交付。**

## 二、色纪律（V3 冻结口径）

1. 深棕主体 / 纸白底（#FAF8F2，禁纯白页底）/ 淡黄点睛 **每屏 ≤2 处**（含选中态/角标/环/dock 激活——超一处即打回）/ 卡其次阶；
2. 禁用清单 grep = 0：#FDC830 / #D97B4A / 深绿 / 纯 #FFFFFF 页底 / 纯 #000000 文字 / 纯黑阴影 / AI 紫光 / 渐变文字 / 默认玻璃拟态；
3. 发丝线半透明染色（rgba(59,46,36,.14/.08)），禁硬实色线；阴影一律向品牌色温染色；
4. 正文对比 ≥4.5:1；数字/金额/时间=mono；屏题=serif；正文=sans——三轨不串，mono 溯源行无折行孤字。

## 三、施工纪律（34 号档 §四/§七/§十 引用）

1. **组件唯一构件库**=规范 §四工艺卡：53 件基础库 + 110 件业务组件逐件过验收尺；先查同型件可复用，确无再向 UX 提新件申请（新件过 UX 评审入册，禁私造构件）；同型异名归并随批执行；
2. **槽位制**：BANNER/卡面/蜡封/线稿/照片/商品图/icon 槽=虚线标注件，内容归素材通道（A5 端口后台直换）；节庆换装不动代码、UX 不为单次换装开工；
3. **字体自托管**：Noto Serif SC（600/700/900）+ JetBrains Mono（400/500/700）woff2 子集化入仓，display=swap，杜绝在线加载闪字；
4. **红线文案 grep = 0**：返现/返钱/疯抢/秒杀/守护值/充值；「年费 ≠ 储值 · 到期不自动续费」明面在位；
5. **四铁律**：不画不存在的功能 / 不改交互步数 / 不丢功能入口 / 不为美观牺牲计时项；
6. **零弹窗**：层叠交互唯一件=底部弹层（抓握手柄+可点遮罩+滚动锁，三件套缺一是废件）；原生 alert/confirm 全域禁止；
7. 实尺验收：390×844 真机或仿真逐屏截图，**对照眼睛不对照文字**；状态栏真实时钟；触件 ≥44px。

## 四、两端方向稿 ↔ 换皮批接口（收口口径）

1. 客户端换皮批 = 按 v2.0 落 token + 构件，依据=34 号档 + 客户端 1.0 定稿，**不依赖两端方向稿**；
2. 员工端/商家端 = 方向稿逐屏 30 屏已展开（S-00~S-12 / W-00~W-16）——**老板 2026-09-27 批：不再逐屏过，直接出《定稿语言包》（逐屏骨架 + 构件映射回 34 号档）交产品侧进施工链；不顺眼的统一走测时再抓**；
3. **补缺专项的新页面 = 换皮后按 v2.0 出生，UX 不提前画**（本件冻结此口径；届时按 34 号档构件库出生即合规，无需单独方向稿）。

## 五、自检记录（军规二）

查了：34 号档全文 + tokens.ts 实证 + 三端 12 文件柠檬黄分布逐点核。发现并已处置：①tokens.ts 的 VI 注释仍是 v9 时代口径（柠檬黄为主色），已列入换皮批必改项——代码改了注释不改=下个窗口又被误导；②philia 渐变横跨双禁色，单列为退役件。残留风险：硬编码 12 文件中 staff 扫码两件（QrScanner/ManualCodeInput）的黄色是扫描框功能色，替换时需 UX 出替代色样（候选=深棕框+淡黄角标），列入换皮批施工示意图注记。

## 六、反对意见与风险（军规一）

1. **tokens.ts 变量级替换有连带面**：`primary` 同时被三端按钮/链接/激活态引用，一键换色后须逐端逐屏过一遍「哪里突然变淡了」——建议换皮批第一批先落 customer 端单端验证，再三端铺开；
2. **两端方向稿未终审是最大上游风险**：若换皮批把员工端/商家端也夹带换色，而方向稿骨架未拍，可能出现「色对了骨不对」的二次返工——建议换皮批范围锁死客户端+R11b 遗留件，两端等语言包。（9-27 老板批②后此风险降级：语言包直接产出，不顺眼走测再抓。）
