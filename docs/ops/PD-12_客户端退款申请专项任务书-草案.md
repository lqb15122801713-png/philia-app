## 一、一句话与边界

客户在自己手机上对**商品单/服务单/寄养单**发起退款申请 → 门店待办审批 → 批准即走 R12 既有链路退（阈值/驳回权/留痕/六联动全沿用，零改动钱链路本体）。
**边界**：退会不走此通道（PD-07 口径既有链路）；申请单≠退款单（申请=客户意图记录，退款=R12 单据）；储值/次卡扣次单=特殊口径（§四待拍）。

## 二、状态机与数据

- **申请单状态机**：`submitted`（申请中）→ `approved`（已批准→自动生成 R12 退款单执行）/ `rejected`（已驳回，强制原因客户可见）/ `cancelled`（客户撤回，仅 submitted 态可撤）；
- **新表一张**：refund_requests（客户/原单/申请金额与行/原因/说明/状态/审批人/审批时间/关联退款单号）——**迁移随批**（任务书冻结时明示）；
- 申请范围校验：原单须 settled 且未全额退；金额 ≤ 可退余额（联 R12 preview 口径同源）；同单重复申请=幂等返回现状。

## 三、三端动作

| 端 | 动作 |
|---|---|
| 客户端 | 订单/预约详情页「申请退款」入口→原因选择+说明（照片可选）→提交→状态全程可见（申请中/已批准/已驳回+原因）；批准后有退款单号可查（透明哲学） |
| 员工端/商家端（门店侧审批闸） | 「退款申请」待办队列（角标+列表）——店长本店/店主全域：批准=自动调 R12 execute（权限闸同矩阵 V1.3：超阈值仍须店主）/驳回=强制原因；日结页待办提醒兜底（推送通道尾欠期） |
| 权限 | 客户=本人单据 only；审批=店长本店+店主全域（V1.3 同族）；全留痕可查询可取证 |

## 四、待拍四问（立项卡挂号件 · 会签时拍）

1. **申请时限**：完成后 N 天内可申？建议=服务/商品单 7 天、寄养单退房后 3 天（端口可调）；未消费单（预约未到店）=不走退款走取消（既有链路）；
2. **部分退款**：默认允许按行申请（R12 按行退既有能力 ✓）；
3. **审批 SLA**：建议 24h 内必复（超时标红待办；推送通道到位后加客户通知）；
4. **储值/次卡单**：储值支付单申请=店主审批（涉储值红线同族）；次卡扣次单=扣次回补通道（任务书定义，次数回充留痕）。

## 五、红线与验收

- 钱红线全域有效：批准才动账；申请层零写入钱域；R12 链路本体零改动；
- 防假功能：审批未落地前客户端入口=明文「内测期请到店办理」第三态禁止；
- 端口：申请开关/时限/原因清单/SLA 全入端口（凡参数皆端口）；
- 验收：QA 用例=申请全流程（提交/幂等/撤回/驳回原因可见/批准联动 R12 退到）；「真实用户能用吗」基准线过一遍（PD-08 口径）。

## 六、自检+反对意见

- 自检：与 R12 冻结版零冲突（申请层纯新增）；与 PD-07 退会边界已划；状态机与既有 refund_bills 状态机分层不混 ✓。
- **反对意见与风险**：①门店审批若无人盯待办=客户申请石沉大海=信任反噬——SLA+日结提醒兜底已写，但**推送通道到位前建议门店每日开店看一次待办**（运营落地）；②客户可申=恶意申请面（同一单反复申）——幂等+同单一申请在途限制作闸；③退款理由清单=内容层，文案键留口不硬编码。
