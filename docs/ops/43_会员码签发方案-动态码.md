## 一、防什么 / 防不住什么（诚实边界先行，CJ-0924-01⑤）

**防**：会员码截图/拍屏转发给他人代享会员权益（服务折扣/回馈金累积归属）。
**诚实写明防不住的边界**：
1. **PWA 做不到系统级禁截屏**——安卓 FLAG_SECURE / iOS 截图检测是**原生能力**，浏览器/PWA 无 API。老板裁定②（安卓禁截屏+iOS 检测警告）在纯 Web 下无法完整落地——**军规一上报：此条裁定与 PWA 技术现实冲突**，本方案给「当前能做到的」+「原生壳留口」两段式（§四）；
2. 拍屏（另一台手机拍屏）任何系统都防不住——**兜底=60 秒时效+一次性核销**，拍出去的码 60 秒后即废；
3. 本人到店本人消费=无需防（会员本人权益自用是正当场景）。

## 二、码值与签发（动态码核心）

- **码值结构**：`base64url(userId.ts.nonce).sig`——sig=HMAC-SHA256(payload, MEMBER_CODE_SECRET)；复用预约核销码同族工艺（BOOKING_CODE_SECRET 已有先例），**密钥独立成 MEMBER_CODE_SECRET**（env 注入，不入仓）；
- **时效**：签发时刻 ts 起 **60 秒有效**，客户端到期自动刷新（码区倒计时可见）；
- **一次性**：nonce 核销端记账（已用 nonce 登记表，60s 窗内唯一约束+事务），同码第二次核销=明文拒绝「该码已使用，请刷新」；
- **验签在核销端**（员工端扫码页/收银台）：验签→验时效→验 nonce→查会员态（membership.forUser 既有端点带出档位/回馈金余额/宠物数）→确认入账；**任何一步不过=明文提示零写入**（防假功能红线）；
- **离线降级**：断网/弱网=手机号报号降级通道（既有 APP-37 手机号识别，R4 断网口径沿用——暂存补传）。

## 三、设备绑定（一账号一设备 · 最严口径）

- **绑定**：账号首次登录即绑定当前设备（deviceId=本地生成指纹+服务端绑定表；绑定时刻/设备信息留痕）；
- **他设备登录**：检测到已绑定他机→提示「该账号已绑定另一台设备」→走换绑；
- **换机换绑流程**：①**正式口径=短信验证**（手机号+短信验证码换绑）——⚠️**短信通道未接（内测期尾欠），本方案留口**：通道接入即开；②**内测期过渡=门店协助换绑**：客户到店，店长/老板在员工端/控制台「换绑」操作（二次确认+强制原因+全留痕可查询可取证，照驳回权同族工艺）；
- 换绑频控端口可调（默认 30 天 1 次，防共享账号串用）。

## 四、截屏防线（两段式：现在能做 vs 原生壳留口）

| 层 | 现在（PWA 能做） | 原生壳留口（后期 APP 化） |
|---|---|---|
| 时效 | 60s 自动刷新+倒计时可见 | 同左 |
| 一次性 | nonce 核销即废 | 同左 |
| 威慑 | **码面水印**：码区叠「昵称+手机号尾 4 位+当前时刻」——转发可溯源到人 | 同左 |
| 禁截屏/检测 | ❌ Web 无此能力（诚实写明） | 安卓 FLAG_SECURE + iOS 截图检测警告——原生壳立项即开 |
| 人脸活体 | 不做（CJ-0924-01④），活体核验接口位留口 | 留口 |

## 五、接口与端口预留（随控制台端口批立项）

- 新端点：`membership.issueCode`（签发，customer）/ `membership.verifyCode`（验签核销，staff/merchant）；设备绑定表+nonce 登记表（迁移随批次）；
- **端口预留**（凡参数皆端口）：码时效秒数/水印开关/换绑频控/绑定策略开关——入 18 号档 C 域（会员卡机制端口附属参数组）；
- 立项批次建议=**控制台端口批首批同批或紧随其后**（核销链路与门店运营面强相关）。
