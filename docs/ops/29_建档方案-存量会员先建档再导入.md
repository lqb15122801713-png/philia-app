## 一、问题定义

储值导入接口（R5b 已交付）按**手机号主键匹配**用户——账面上的人必须先在系统里「存在」（有 users 档案），否则存量会员的储值无处落账。建档≠现场注册：批量预建档，客户首登（手机号）即激活并看到迁移过来的余额。

## 二、执行序列（切换日，五步全留痕）

| 步 | 动作 | 通道 | 状态 |
|---|---|---|---|
| 1 | **建档 dry-run（零写入对账报告）**：读台账 CSV → 拟建档 N 人（排除已建档）/三店分布/异常行逐条列出——零写入，运营先核 | 批量建档端点（dry-run 模式）——**待建，进切换日执行包任务书** | 📝通道待建 |
| 2 | **建档执行**：批量创建 users 档案（手机号主键幂等：已存在=跳过标「已存在」）；建档批次号+逐行留痕（谁/何时/台账行号） | 批量建档端点（execute 模式）——**待建，同上** | 📝通道待建 |
| 3 | **储值 preview 对账**：建档后跑 preview——校验位必须与**切换日当次导出**台账吻合（§十二：校验位以当次导出重采为准） | `storedValue.previewImport`（R5b 既有，零写入） | ✅通道就绪 |
| 4 | **储值导入 execute**：批次留痕+试导可清除（已消费批次拒清） | `storedValue.executeImport`（R5b 既有，仅 owner） | ✅通道就绪 |
| 5 | **复走抽验**：运营按抽验口径逐会员抽核（余额/归属店/次卡）；产品侧出对账比对工具（台账 vs 库内逐人 diff） | 抽验=人工+比对工具（执行包组件） | 📝工具待建 |

**执行前置**：全库备份（DEPLOY §5 停写拷贝 philia.db）+老板书面授权（按按钮=产品侧执行）。

## 三、口径钉死

- **手机号主键**：会员编号缺失不影响（手机号为唯一事实源）；同一手机号多行=同一人，储值按行累加（接口事务内重读账户，R5b 代码实证）。
- **三店归属**：客户档案全局唯一（中央一本账，决策 #41）——门店归属不落 users，落在**储值账户行**（stored_value_accounts.store_id=台账门店列映射）；余额中央通用。
- **次卡夹带**：R5b 接口仅计数预留（passCarryRows）——**正式承接=通用次数包域**（CJ-0923-18，39 号档评估：洗护直接映射+寄养扩品类+¥0 附随同域；映射表=34 号档）。「150」口径已复核断裂，见 §十二。
- **幂等**：建档=手机号查重跳过（不产生双份）；储值 execute **无文件级幂等**（R5b 代码实证：重复 execute 会重复入账）——纪律=正式导入一次性执行，试导走 clearImportBatch 清除后重导。
- **防假**：任何一步校验位与台账不合=停，不许「差不多就导」。
- 建档**静默**：不触发任何通知/营销动作，首登才激活感知。

## 四、与会员体系（R11a 已上线）的关系

建档出来的客户默认**非会员**（无档位）；微光档=客户首登后自助一键开（R11a 已上线）；存量付费会员识别=**台账无会员档位列（36 号档已答：全空=没有）**——切换日只迁储值/次数包，档位由到店首单时店员协助开通（29 号档原预案生效）。

## 五、字段级映射表（V1.0 补齐件①）

### 5.1 台账 CSV 实读列（以 R5b 接口 LEDGER_COLUMNS 代码实证为准）

接口按**表头名**定位（列序错位容错）；必要列缺列=整单拒绝不猜列序。**⚠️ 列名须按切换日实际导出模板重校（§十二.3 硬要求）**：

| 台账列名（9-17/18 采集模板） | 系统落点 | 转换规则 |
|---|---|---|
| 门店 | 储值账户 store_id | 入参 mapping {台账店名: storeId}（贝肯山店/生活馆店/生态城店三行映射，未映射行失败留痕） |
| 会员编号 | **不入库** | 缺失行多，不作主键；编号留 CSV 存档 |
| 会员姓名 | users.nickname（建档时） | 空则落「新客 <手机号尾 4 位>」（同 membership.sell 旁路建档口径） |
| 手机号码 | **users.phone（主键）** | 建档：查无则建（kimi_id='phone:<手机号>'，user_roles+customer）；导入：查无则失败留痕「会员未建档」 |
| 会员卡名称 | 不入库 | 旧卡体系随储值转型作废（新售冻结） |
| 储值本金余额(¥) | stored_value_accounts.principal_fen | 元→分两位小数；容错 ¥/￥/千分位/空白（空=0）；负数/非法=失败行 |
| 储值赠送金额(¥) | stored_value_accounts.bonus_fen | 同上；本金/赠送分列（账目四分列口径） |
| 次卡名称 | 通用次数包域（39 号档） | 映射表=34 号档；导入通道待建 |
| 次卡剩余次数 | 同上 | 同上 |

### 5.2 建档写入（待建端点字段级规格）

| 系统字段 | 取值 | 说明 |
|---|---|---|
| users.id | 系统生成 | 文本主键 |

| users.nickname | 会员姓名 / 「新客 尾 4 位」 | — |
| users.phone | 手机号码 | 主键幂等键（**注意：schema 层 phone 无唯一索引，唯一性=应用层口径**——见 §十一 风险②） |

## 六、异常行处置细则（V1.0 补齐件②）

**总原则：异常行零写入+逐条留痕（行号+原因）+回运营核对，不猜不改台账。**

| 异常 | 触发 | 处置 |
|---|---|---|
| 手机号缺失/非法 | 非 1 开头 11 位 | 不建档不导入；列异常清单回运营补录后随补录批再跑 |
| 手机号重复（同号多行） | 同号多行 | 正常情形=同一人多笔台账：建档一次，储值按行累加；dry-run 报告列「合并人数」供运营核 |
| 会员编号缺失 | 编号列空 | 不影响（编号不作主键），报告计数留痕 |
| 门店未映射 | mapping 缺该店名 | 行失败留痕；三行映射是必填前置，dry-run 先炸出来 |
| 会员未建档 | 储值导入时查无 users 行 | 建档先行的意义所在；preview 阶段此原因应=0，>0 即停 |
| 金额列非法 | 本金/赠送非 ≥0 数字 | 行失败留痕回运营 |
| 库内手机号已存在 | 建档查重命中 | 跳过标「已存在」——**但若命中的是测试号/演示号占了真实客户手机号=红色异常**（见 §十一 风险②） |
| **列名不匹配（V1.1 增）** | 切换日导出模板列名≠LEDGER_COLUMNS | **整单拒收是设计保护**（不猜列序）——按 §十二.3 先校列名再喂，不许硬改 CSV 凑合 |

## 九、回滚预案（V1.0 补齐件⑤）

1. **总闸**：切换日执行前全库备份（DEPLOY §5：停写→拷贝 philia.db→启）；任何一步校验位不合=停，必要时恢复备份重来。

4. **次数包回滚**：随通用次数包导入通道任务书同规格设计（批次留痕+可清除+已核销拒清，39 号档）。

## 十二、「150 口径」复核结论（V1.1 · 老板令③，2026-09-23）

**复核结论：150 与新实况对不上，断裂原因=采集模板口径不同——原 150 校验位作废，以切换日当次导出重采为准。**

1. **当年 150 怎么来的**：9-17/18 采集用电脑客户端旧版导出模板，「次卡剩余次数」为单值列——150=该口径下次卡剩余次数>0 的行数（R5b passCarryRows 同口径计数）。
2. **今日实况（34 号档 §三/§四，9-23 20:05 导出）**：网页版导出为「次卡名称/次卡可消费次数」复合串（含会员卡附赠权益）——带次数包行 1162 行/1161 人（剩余>0 者 1111 人），任何口径都复算不回 150。**两模板列名也全不匹配**（旧：储值本金余额(¥)/次卡剩余次数；新：会员卡本金/充值余额、次卡可消费次数）。
3. **硬要求（切换日执行包收编）**：①**列名映射层**——R5b 必要列定位从「精确表头名」升级为「别名映射表」（旧新两套模板列名都认），缺必要列仍整单拒收（防假不降级）；②**校验位以切换日当次导出重采**——29 号档旧校验位（1290/907/¥671,264.42/1286/728·328·234/150/344）全部作废封存，仅作历史对账参照；③次数包夹带新基线=1162 行/1161 人（剩余>0=1111 人），随 39 号档通用次数包域导入。
