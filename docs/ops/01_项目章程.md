# Philia 项目章程

> 本档案发给谁：老板本人 + 各角色窗口（产品/运营/项目经理/QA/监理/设计/数据分析）。
> 性质：项目"宪法"——不轻易变动的定位、目标、优先级、审美取向。变动需老板拍板后由项目经理窗口修订。
> 最近更新：2026-09-21（首版，依据 9-18/9-19 老板裁定整理）

---

## 一、项目定位（2026-09-18 老板确立，可商量调整）

1. **商业模型**：小而精的社区精品宠物店，服务对标亚朵/海底捞。从现有三店精细化改造开刀，跑通模式后按"开店闸门"复制，长期目标开遍全国的真正连锁。
2. **APP 定位**：宠物垂类。现阶段线下引流线上；未来线上引流 + 线上购买 + 线下体验的全生态。
3. **利润底座**：年费会员（山姆模式）。

## 二、三端结构

- **客户端**：宠物主人使用，预约/服务进度可视/会员。
- **员工端**：店员/店长使用，服务 SOP 执行（六步）、层级权限（老板/店长/店员）。
- **商家端**：一个 codebase 两个工作区（CJ-0921-03）——**门店端**=店员/店长本店执行面（收银/日结/审批/库存，只见本店）；**老板端**=店主三店总览驾驶舱+全局管控（配置端口/权限矩阵/商品导入/会员互通规则，可下钻任意店）。对标宠老板连锁模型，但会员卡体系为"中央卡全通用"（卡在中央不在店/人是一本账/账按店双归属），优于宠老板"分店建卡点通用"。
- 三端必须打通；会员/宠物档案全局一本账，单据必带办卡店+消费店双归属。

## 三、当前阶段优先级（2026-09-18 老板阶段定调）

1. 功能调整
2. 客户端极致体验
3. 员工端层级易用（老板/店长/店员权限矩阵）
4. 商家端整体把控（对标宠老板/银豹）

**UI 实施排最后**（仍是高度重视必解项）；方向稿取材/评审照常进行。

## 四、审美取向（终审标准）

- 老板审美 = **高端品牌感，而非工具平台感**。否决过"非常普通、没有非常 NICE 的感觉"的 UI。
- UI 验收中，细节分析与老板整体感觉冲突时，**以老板感觉为准**。
- 参照系：世界一流 App 设计（Mobbin 标杆库，经产品侧代查调取）。
- **审美基准样张**：《11_老板审美基准样张》（客户端 v9.1，老板 9-21 确认）——产出只能高于它。

## 五、验收总线（不可降级）

- "能点"只是底线；**视觉体验与动效质感才是验收线**。
- 与方案示意图不一致的 UI 直接打回重做，不得呈老板。
- P0 验收以真机三端走测为准；**代码覆盖 ≠ 体验达标**。
- 交付三件套：三端走测图 + 对账表 + 发放说明（这份发给谁）。缺一件打回。
- 发给人看的交付文件一律中文文件名；仅直接进代码仓库的技术附件可用英文名并标注"技术件"。
